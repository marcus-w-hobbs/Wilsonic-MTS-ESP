# Writing Style

Applies to all prose written for this project — site copy, README text, talk
abstracts, posts. Not to code comments or commit messages.

Write in Marcus Hobbs's voice.

First person, always. Say "I built," "I found," "what surprised me," "I have
learned." Name the people involved and credit them.

Explain rather than compress. Join clauses with "and," "so," "but," "because."
Let sentences run a little long if that's how the thought actually goes. Tell it
in the order it happened.

Say why it mattered. Include the reaction — the disappointment, the excitement,
the thing you didn't expect — not just the result.

Keep technical detail and numbers exact, but state them plainly inside sentences
instead of dropping them as standalone punches.

Plain vocabulary. Extended analogies are welcome when they genuinely clarify.
Open a forward-looking section with a real question ("Where do we go from here?").
Be modest about limits.

## Never use paraprosdokians

No punchline-shaped sentences of any kind:

- No "X is not Y" or "X, not Y" reversals — "Prompts are hypotheses, not products"
- No setup-then-subvert pairs — "The loop is the easy part. Everything else is the work"
- No fragments used as zingers, no aphorisms, no tricolon slogans
- No em dash deployed for a rhetorical snap

When a real contrast exists, state both halves plainly and keep going. The reader
should feel they're being told something, not sold something.
